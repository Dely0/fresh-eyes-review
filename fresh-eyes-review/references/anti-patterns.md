# 无效发现长什么样，以及怎么处置

审查者的产出**必须过滤**。这不是不信任它，而是所有实证都指向同一件事：一个 AI 审查者报出来的东西，好坏混杂，而"看起来合理"和"真的成立"之间的差距，只能靠证据跨过去。

## 一、按这四条分流

| 收到的东西 | 判定 | 处置 |
|---|---|---|
| 有位置、有复现命令、有可重放的证据，且你照抄能重现 | **有效** | 修，并补一个反向断言 |
| 三要素齐了，但你照抄跑不出同样结果 | **存疑** | **升级给人判断** —— 可能是环境差异，也可能是编造；不要直接采信，也不要直接当指控 |
| 缺复现或缺证据，但位置和影响写得很像回事 | **无效** | **直接丢弃或退回补证据。绝对不要凭它改代码。** |
| 只有"建议考虑"、"可能存在"、"注意一下"这类判断 | **噪声** | 丢弃，不回复 |

判定标准只有一句：**别人能不能照着这段文字复现出同一个结果。** 不能，就不是证据。

## 二、最常见的六种无效发现

1. **"建议为这里加上错误处理 / 边界校验"** —— 没说哪个输入会炸、也没跑过。改进建议不是发现。
2. **"这里可能有并发问题 / 内存问题 / 性能问题"** —— 猜想。要求它给出触发时序或压测数据，给不出就丢。
3. **只回一句"我已检查，未发现问题"** —— 无法区分"真的没有"和"没认真看"。退回：**要求列出你实际执行了哪些命令、读了哪些文件。**
4. **编造的输出** —— 这是真实发生过的事故类型，不是理论风险：有项目（`andrewstellman/quality-playbook`）就是因为模型**执行了命令却把自己编造的期望输出写进证据文件**，才给门禁加了"落盘 + 重跑 + diff"这一层。所以现在格式要求证据落盘，`--replay` 档会重跑比对。发现一次就要整体降权，并明确告诉它"编造输出比不报更糟"。
5. **只报低危（命名、格式、注释）刷屏** —— 要求按严重度排序、只保留高危；低危单独折叠到末尾。**高危数量没有上升时，"多一个审查者"其实是零收益。**
6. **锚定在 diff 上** —— 只报改动的那几行，不看调用方、不看测试、不看文档。明确要求：至少检查一处改动之外的连带影响。
7. **位置是编的** —— 命令能跑、证据文件也对得上，但位置指向一个**根本不存在**的文件和行号。幻觉路径是 LLM 的典型失败模式。门禁会核实（`--strict` 下算不合格）；位置解析不出来时，自己扫一眼那个文件在不在。
8. **命令与发现不匹配** —— 这条最隐蔽：命令**真的跑了**，证据文件**也真是它的输出**，重放**也一致**，但那条命令**根本不能证明这条发现**。三个实测过的样子：
   - ✅ **恒真命令 + 证据记成 exit 0** —— 被机械堵住。反向前置证据的退出码必须**非零**，`assert True` 永远是 0，四个档位都判不合格。
   - ✅ **恒真命令 + 前置证据伪造成 exit 1** —— 只有 `--pre-fix` 抓得住（只有它会在改之前真的重跑那条命令）。**这就是 `--pre-fix` 不能省的原因**：默认档、`--strict`、`--replay` 都会放行。
   - ⚠️ **碰巧失败的无关命令** —— 最隐蔽的一种。攻击者找一条在「有缺陷」和「没问题」两种代码上都失败的命令：退出码非零，`--pre-fix` 照样复现。**`--replay` 会因为「前置命令没转绿」把它拦下**（那条命令在修完之后仍然失败）；但如果作者真的把缺陷修好了，只是这条命令选得与结论无关，那就只剩人判断。门禁验不了"这个失败是否指向那条结论"。

   **所以仍然要问人那句：这条命令如果跑在「有问题」和「没问题」两种代码上，输出会不一样吗？** 不会不一样，它就没有证明力——不管它是恒真、伪造还是碰巧失败。

## 三、退回话术（照抄即可）

**先说清退回的机制**：前台起的 subagent 结束后没有可寻址的 id，叫不回同一个审查者。所以"退回"= **重开一个空上下文的审查者**，把原报告一起发给它，并写明"只许补证据、不许重报、不许改结论"。这样做同时保住了独立性。

退回后的记录要注明**哪几条是当场证据、哪几条是后补的** —— 后补的证据强度不如当场跑出来的。

```
下面这份报告里有两条缺证据。请只针对 F3 和 F7：
给出能被别人照抄执行的命令，把原始输出落盘成证据文件（首行 [exit code: N]），
并在报告里写上证据文件路径。跑不了就写「未能执行：原因」。
不要重报其他条目，也不要改结论。

<原报告全文>
```

```
报告里只有一句「未发现问题」。请补两件事：
① 你实际执行了哪些命令、读了哪些文件（附证据文件）；
② 你判断"没问题"依据的是什么。
然后再说一次结论。
```

## 四、退出码怎么读

格式门禁 `check_review_report.py` 只回答"写了没有"，`--pre-fix` 回答"缺陷真的被观察到失败没有"，`--replay` 才回答"真的跑过没有"：

| 退出码 | 含义 | 你该做什么 |
|---|---|---|
| 0 | 每条都带齐位置 / 复现 / 证据 / 反向前置（`--pre-fix` 下还要求前置命令仍然失败；`--replay` 下还要求全部重放一致） | **默认档下仍然要自己核实内容**；`--pre-fix` / `--replay` 通过的可以放心用 |
| 1 | 有条目缺证据，**或反向前置证据记成 exit 0**（命令通过了＝缺陷不成立），或前置/重放未按要求表现 / 被拒绝表拦下；`--strict` 下也包含「位置不存在」「缺反向前置」这类提醒 | 缺证据的退回或丢弃；**「前置证据记成 0」等于这条发现不成立**，直接退回；重放不一致的升级给人判断 |
| 2 | 报告读不了（缺文件、未知参数、编码解不开），或 `--pre-fix` 与 `--replay` 同时给出 | 先修编码/路径/参数 —— **这是读取错误，不是"报告不合格"**，两件事不能混 |

`--strict` 会把"缺严重度""位置没行号""**位置指向不存在的文件**""**缺少反向前置**"这类提醒也计为不合格（退出 1），适合接 CI；默认档只把它们当建议。

### `--replay` 的边界（别误解它）

- **它不是沙箱。** 它会在你指定的目录里执行报告里写的命令，只有一层"防手滑"拒绝表和超时。**只在你读过、且愿意让那些命令碰过的报告上开。**
- **重放一致 ≠ 结论正确**，只证明"这条证据是真的跑出来的"；判断这条发现是否成立、要不要修，仍然是你的事。
- **重放不一致 ≠ 造假**，也可能是环境、数据、依赖版本不同。它只说明"这条现在没法被第三方重放"，按存疑处理并升级给人才是对的。
- **`--replay` 不足以替代 `--pre-fix`。** 伪造前置证据退出码、命令却是恒真的，只有 `--pre-fix`（改之前真的重跑）能识别。任何真实使用都要在动手改之前跑一次 `--pre-fix`。
- **「命令有没有证明力」它验不了。** 见第二节第 8 条：一条**碰巧**失败的无关命令可以骗过默认档与 `--pre-fix`；`--replay` 只在它修完后仍然失败时才拦得住。这一条最终仍要人判断。
- **假失败率还没被测过。** 归一化只折叠十类已知易变 token（时间戳、耗时、uuid、临时路径、pid、地址……），不在表里的易变内容（随机哈希、端口号、乱序输出）会让重放判"不一致"。这是有意选的保守一侧（宁可多升级给人，也不能让编造的证据被放行），但**如果假失败的比例太高，人就会干脆不用 `--replay`，那这一档就白做了**。所以请自己量一下：拿真实项目跑 5~10 次，记录「真差异」和「环境噪声」各占多少。这个数字目前是空的 —— 在它被量出来之前，不要对外声称 `--replay` 已经「可用」。

## 五、收口：每条修完都要能变红

审查只完成了一半。每修一条，**补一个断言并把它反向验证一遍**：把 bug 故意装回去，测试必须变红。

- 红不了 → 说明断言没咬住，**继续改断言，不是继续改代码**。
- 这一步把"有人看过"变成"机器以后一直看着"，也是整套流程里**最值得优先做的那一条**（会留下长期资产）。

## 六、别指望的事

- **别指望多一个 AI 审查者提高高危缺陷的捕获率。** 有对照实验（29 名专家、50+ 小时）显示：LLM 报的问题大多有效，但会带来锚定效应，低危发现变多、**高危发现没有增加**，而且没省时间。
- 真正抬高上限的是三件事：**让审查者能跑命令**（而不是静态读 diff）、**强制它交可重放的证据**、**用反向验证收口**。
- 另外一条经典反证：Knight & Leveson 1986（DOI `10.1109/TSE.1986.6312924`）证明"独立开发"的实现**仍会共同失效** —— 隔离不等于错误不相关。想要真正的独立性得换**来源**（模型族、上下文、提示词框架），不能只换数量。
