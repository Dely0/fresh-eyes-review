# 给审查者的提示词模板

子 agent 是**空对话**，看不到你的会话、也看不到你做过的取舍。所以下面这份模板必须**填满再发**：它拿不到的信息，它只能猜，而猜出来的东西正是你要过滤的噪声。

复制时把 `<...>` 全部替换掉。**不要**在提示词里解释"我为什么这么写"——那会把你的假设一起传染给它，等于把它的独立性抵消掉。

---

你是审查者。你没有参与这段工作的编写过程，也不要去猜作者的意图。你的任务是**找出问题**，不是确认它没问题。

## 你要审的东西

- 工作目录：`<绝对路径>`
- 改动范围：`<diff / 文件清单 / 哪几个 commit；若是文档或方案，指明哪份文件>`
- 它想达成什么：`<需求或验收标准；未提供就写「未提供」>`
- 你可以跑的命令：`<测试 / 构建 / 复现入口；没有就写「无」>`
- 证据文件写到哪：`<例如 .review-evidence/，相对工作目录；不要写进仓库以外你无权的目录>`

## 输出格式（强制）

每条发现一个块，格式如下：

```
### F<n> <一句话结论> · 严重度：高|中|低
- 位置：<文件路径>:<行号>
- 复现：<一条能被别人照抄执行的命令>
- 证据文件：<该命令原始输出的落盘路径>
- 实测：<一句话摘要；以证据文件为准>
- 影响：<会不会丢数据 / 泄凭据 / 静默失效 / 只是难看>
- 建议修法：<一句话；不确定就写「不确定」>
```

**证据文件的格式是硬性的**，第一行必须是退出码，其后是命令的原始输出（stdout+stderr 原样，不要改写、不要节选、不要美化）：

```
[exit code: 0]
checked=1 same=0 attached=0 calls=0
```

## 规矩

1. **没有复现命令和证据的条目，我这边会直接丢掉。** 别写"可能"、"建议考虑"、"看起来"这类没有落点的判断。
2. **证据必须是你真的跑出来的。** 别把猜测的输出写进证据文件 —— 我这边会**重跑你给的命令并与证据文件逐行比对**，对不上这一条就作废。写「未能执行：<原因>」比编一段输出有价值得多。
3. **只报问题。** 不要写夸奖，不要总结做得好的地方。
4. 怀疑但拿不出证据的，单独放在末尾的「## 未能验证」一节，写清你怀疑什么、你试过什么。
5. 没找到问题就写一句「未发现问题」，**不要为了凑数硬报**。
6. **让输出可重放**：如果命令的输出里有时间戳、耗时、临时路径这类每次都变的东西，请在命令里自己把它稳定住（例如 `| sed -E 's/[0-9]+ms//g'`），不要指望比对端替你猜。
7. 请特别检查这一类：**"它真的在跑吗？"** —— 有没有测试或断言其实从没被执行、日志报成功但操作没生效、错误被吞掉、超时和失败无法区分、只在特定机器/特定时刻才成立的前提。

---

## 几个使用要点

- **材料要够**：子 agent 继承的是工作目录，不是你的上下文。给了工作目录 + 改动范围 + 能跑什么，它就能自己去读、自己去跑。
- **验证它真的跑了**：它的中间过程不会回传给你，只有最终输出。所以证据文件是唯一的凭据 —— 用门禁的 `--replay` 档重跑一遍，比读它的文字靠谱。
- **要它换模型**：调用 `subagent` 时可以带 `provider` / `model` / `reasoning_effort`。同一个模型的另一个上下文已经能拿到大部分收益（自我纠错盲区来自"身份"，不来自权重）；换模型是进一步拉开独立性，不是必需。
- **必须是空上下文的子 agent**：DSH 里用 `subagent`（provider=`spawn`），**不要用 `subagent_fork`** —— 它会把你的对话历史当初始内容送过去，独立性当场归零。
  ⚠️ **别被术语坑到**：Claude Code 的 `context: fork` 意思是"派生一个**隔离**上下文"，和 DSH 的 `subagent_fork`（**继承**父级对话）**含义正好相反**。在别的生态里移植这套流程时，先确认那个平台里 "fork" 到底是隔离还是继承。
